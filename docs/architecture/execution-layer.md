# 执行层设计（0 号场景）

> **状态：部分被取代（2026-09-30）。** 执行载体已改为 Postgres 本体 + Action 引擎（ADR-0006 / 0009），抽取由 `autobiz extract` 执行；定时调度待补。下文的触发矩阵与打分阈值仅作历史参考。

执行层回答一个问题：`ontology/actions.yaml` 里的 10 个 Action，由谁、在什么时候、以什么方式执行。

## 执行模型：任务队列 + runner

复用已有的 runner 约定（data/tasks 任务队列）：

```
触发器 ──> data/tasks/<id>.json ──> runner 按 node+action 路由 ──> 节点技能执行
                                                              │
                              读写飞书投影（lark-cli）<────────┤
                                                              ▼
                                        data/results/<id>.done.json（执行日志，自建留存，ADR-0001）
```

- **任务** = 一次 Action 调用：`{ action, input: {对象引用}, created_at }`，按 created_at 顺序消费
- **节点技能是 Action 的适配器实现**：现有收录/处理/选题/长文/短文/配图/视频/口播/资产九个节点技能直接挂到 Action 上；底层换成代码生成视频或豆包 Agent 时，只换适配器，Action 接口不动
- **幂等**：靠状态机守卫（如 process_material 只消费 status=未处理 的素材）；失败任务保留现场，可重投

## 触发矩阵

| Action | 触发方式 |
|---|---|
| ingest_material | 定时同步（每小时）+ 手动触发；Obsidian → 飞书单向推送 |
| process_material | ingest 完成后自动链式触发 |
| propose_topics | 素材判高分后自动；也支持手动"从高分素材生成 10 个选题" |
| finalize_topic | **人工闸门**：人在飞书看板把状态改为"已定档"；runner 每 10 分钟轮询"已定档且无母版"的选题，自动触发下游 |
| generate_master / generate_variant / review_variant | 上游完成后自动链式触发 |
| mark_published / backfill_metrics | 人工在飞书表内直接填写（不走任务队列） |
| run_feedback | 定时任务，每周一次 |

## 品牌DNA 约束（所有生成 Action 的前置输入）

- 唯一事实源：`brand-dna/` 目录五份 md（01 个人 / 02 品牌 / 03 客户 / 04 定位画布 / 05 钩子库）
- 生成节点（母版/变体/口播稿/配图/视频）执行前读 `brand-dna/生成上下文.md`（派生摘要）
- 硬规则：禁说词自检（惊呆了/夯爆了/屌爆了/太炸裂了）；不贩卖焦虑；招牌句自然植入
- 选题来源双通道：素材库高分素材 + 钩子库「保留」钩子

## 打分器契约（process_material 的核心）

- 输入：素材原文 + 品牌DNA 摘要
- 输出：四维分（相关度/信息密度/可操作性/时效性，各 0-10）+ 综合分（0-100）+ 分类 + 标签 + 重点摘要
- 综合分 = 相关度×4 + 信息密度×2 + 可操作性×2.5 + 时效性×1.5 + performance_boost（反馈环项，冷启动期恒为 0）
- **相关度闸门**：相关度 < 4 时综合分封顶 39，直接判无价值——质量再高但与业务无关的内容不允许入库（2026-09-26 首批实测时确立：苹果选购指南类内容密度虽高，与本业务无关）
- 双阈值路由（初值，跑两周后校准）：综合分 ≥ 75 → 已入库并触发选题建议；< 40 → 无价值；中间 → 已入库静放

## 反馈环（run_feedback，每周）

1. 聚合：每条发布记录取最新快照 + 获客归因
2. 沿溯源链归并：发布表现 → 资产 → 变体 → 母版 → 选题 → 素材簇
3. 写回：素材.performance_boost（机器加权）；选题.similar_history（同类历史表现摘要，供定档人参考）
4. 冷启动：发布记录 < 20 条时只生成 similar_history 展示文本，不改 performance_boost

## 失败策略

- 变体体检 rejected → 自动重新生成，**最多 2 次**；仍失败则转人工（资产 review_mode=人工介入）
- 任务执行失败 → 结果文件如实记 failed，不静默吞错；可人工重投

## 不做什么

- 不用飞书 Workflow 承载业务规则（投影纪律，ADR-0001）：Workflow 只允许做"提醒类"轻自动化
- 不在执行层引入常驻服务：当前规模下，定时唤起 + 任务队列足够；未来迁移开源栈时再评估常驻化
