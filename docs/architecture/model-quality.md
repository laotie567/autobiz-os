# 模型质量管控：在国产模型上保住业务质量

前提（ADR-0008）：设计期用 Claude，生产期用豆包 / DeepSeek / GLM / Kimi。
设计目标：同一套系统从 Claude 换到国产模型后，业务质量的下降**可预期、可度量、可兜底**。

## 一、质量会在哪里掉（影响因子）

| # | 影响因子 | 对应业务环节 | 掉质量的表现 | 风险 |
|---|---|---|---|---|
| F1 | 结构化输出合规 | 知识抽取、打分 | JSON 缺字段、枚举值自造、类型错 | 高：直接写坏本体 |
| F2 | 抽取准确度 | 痛点 / 案例 / 方法抽取 | 把观点当案例、编造效果数据、漏抽 | 高：污染行业地图 |
| F3 | 实体消歧与合并 | extract_knowledge 合并 | 误合并（Coze ≠ 扣子插件）、重复节点 | 高：错误难发现、难回滚 |
| F4 | 多步推理 | 学习缺口、选品判断、方案建议 | 跳步、结论与证据不符 | 中 |
| F5 | 工具调用稳定性 | 豆包 Agent 调用 MCP 工具 | 选错工具、参数错、循环调用 | 中 |
| F6 | 长上下文 | 长文章、妙记、项目文档 | 后半段信息丢失 | 中 |
| F7 | 幻觉 | 对外内容、客户方案、课件 | 编造数据、案例、出处 | 最高：伤信任，违背"不忽悠" |
| F8 | 风格遵循 | 内容生成（品牌DNA） | 出现禁说词、焦虑营销腔 | 中 |

## 二、七条设计原则（顶层设计）

1. **本体做推理，模型做窄活。** 行业地图、学习缺口、打分加权、选品指标计算，一律写成确定性的函数（代码 / SQL）。模型只负责"读一段文字 → 填一张表"这类窄任务。任务越窄，强弱模型的差距越小。
2. **任务拆小，一步一张表。** 抽取不做"一次抽全部"，拆成：相关度判定 → 按对象类型分别抽取 → 合并判定。每一步的输入输出都短而明确。
3. **输出必须过代码校验。** 所有模型输出按 JSON Schema 校验，枚举值只能从本体里选，引用必须是原文片段（F7 的核心防线：抽取的案例效果必须附原文引文，找不到引文就丢弃）。校验失败自动重试一次；仍失败则进待办，不静默写入。
4. **不确定就交给人或升级模型。** 输出带置信度。低置信度对象、合并操作中的"疑似同一实体"，进入待确认队列，不自动执行。
5. **对外出口有闸门。** 沿用 verified 规则：只有人工确认过的知识，才能进入课件、方案、发布内容（F7）。
6. **工具面向业务而非面向数据库。** 给豆包 Agent 的 MCP 工具数量少（当前 14 个）、粒度粗、中文描述带示例，比如"查某行业全景"，而不是"执行 SQL"。写操作工具必须先展示预览再确认（F5）。
7. **一切可追溯、可重跑。** AI 写入的对象记录 extracted_by（模型 + 提示词版本）。发现某版本质量差，可按版本定位并批量重跑。

## 三、过程管控（怎么持续知道质量没掉）

```
设计期（Claude）                         生产期（国产模型）
───────────────────                     ─────────────────────────
① Claude 产出黄金评测集                  ④ 模型路由按任务类型选模型
   每类任务 30-50 条标准答案                 （配置文件，可随时换）
② Claude 写提示词 + 校验规则 v1          ⑤ 代码校验 + 置信度分流
③ 在国产模型上跑评测，调到达标            ⑥ 每周抽样审计：Claude 抽查 5%
   → 记下各任务的"质量基线"                 生产输出，对比基线出周报
                    ↑                                  │
                    └──── 低于基线 → 调提示词 / 换模型 ─┘
```

- **评测门槛（初值，跑两周后校准）**：结构化合规 ≥ 98%；抽取准确率 ≥ 85%；误合并率 ≤ 2%；对外内容幻觉率 = 0（有闸门兜底）。
- **换模型或改提示词的规矩**：先跑评测集，达到基线才能切换，跟代码合并前跑测试一样。
- **抽样审计**是 Claude 在生产期的唯一常驻角色：用量小、成本低，负责"验收"。

## 五、代码开发流程（Claude 设计验收 + 国产模型执行）

同样的原则用在写代码上：**让执行者的产出可以被机器判定对错。**
1. Claude 写接口契约与测试（先有红灯测试）。
2. 国产模型（GLM / DeepSeek / Kimi）写实现，直到测试变绿。
3. Claude 审查 diff（标准 + 需求两个维度），不合格退回并写明原因。
4. 任务切小：单个任务只动 1-3 个文件，并附明确的完成判据。
