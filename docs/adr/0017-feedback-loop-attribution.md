# 数据回流：批量回填、线索按关键词归因、形态线索率（S3）

2026-10-16。触发：周发布 50 条后，24h / 72h / 7d 三个时点手工回填 = 每周约 150 次，不可持续；
线索只挂到"发布记录"一层，回答不了"哪种形态、哪个钩子关键词真正带客"——而这是下周配比怎么调的唯一依据（ADR-0003 反馈环）。

## 决定

- **只强制回填 7 天数据，截图批量写入**：`backfill_batch` 接收豆包从创作者后台截图识别出的多条数据，
  按发布记录 id / 链接 / 标题（忽略空格标点 → 包含 → pg_trgm 相似度且明显领先）匹配；
  **匹配不唯一就不写**，列候选让人确认——宁可少回填，也不错回填。
- **线索按私信关键词自动归因**：发布记录带 `keyword`（内容件发布时从创作包继承），`quick_lead` / `create_lead`
  带关键词时归到近 14 天带同一关键词的发布，同平台优先、其次最近；记 `attribution=keyword_auto`。
  归不上的进"待认领"，`attribute_lead` 人工认领（`manual`）。
- **形态线索率**：`format_performance` 按形态、按关键词统计发布数、线索、每条线索、平均播放；线索数取
  "回填的私信 + 加微数"与"关联线索数"的较大者（与 content_performance 一致）。
- **只用实测，不预设**：数据跨度满 28 天、且至少 2 种形态各发满 3 条，才给"减 2 条 / 加 2 条"的配比建议；
  真人口播是每日硬指标，不参与调整；建议由用户确认后改 profile。`conversion_stats` 同理，满 28 天才给实测转化率。

## Consequences

- 关键词是归因的主键：快产线创作包里的 `keyword` 要有区分度（一条内容一个关键词最好），否则归因只能落在"最近一条"。
- 截图识别由 Agent 完成，系统不做 OCR；识别错误由"匹配不唯一不写"兜底，但数值识别错误需要用户抽查。
- 周报新增：近 30 天形态线索率、关键词带客、配比建议、实测转化（数据够时）、待认领线索数。
