# 模型分工：Claude 负责设计与验收，国产模型负责生产运行

生产运行与客户侧必须使用国产模型：token 成本；豆包是全自研全模态模型，与飞书衔接顺滑，支撑持续的短视频内容产出；客户侧（粉丝、企业客户）使用豆包与 DeepSeek。

决定：
- 系统设计与建设期：Claude 做架构设计、代码审查、验收。
- 生产运行：豆包为主（抽取、问答、内容生成、多模态）；日常交互入口是豆包的 Agent 界面。
- 客户交付：豆包 / DeepSeek 可切换。
- 专有代码开发：Claude 做架构、审查、验收；GLM / DeepSeek / Kimi 等国产模型执行编码。

## Consequences

- 系统不能假设"模型足够聪明"。业务质量要靠结构兜底，而不是靠模型智力：本体承担推理，模型只做窄任务（详见 docs/architecture/model-quality.md）。
- 任何代码不直接调用具体模型 API，一律经模型路由层按"任务类型"选模型；换模型改配置，不改代码。
- 每类 AI 任务都要有 Claude 在设计期产出的黄金评测集。换模型、改提示词之前先跑评测，不达标不上线。
- AI 写入的每个对象都记录产出它的模型与提示词版本，质量问题可按模型追溯、批量重跑。
- 日常入口是豆包工作（类 Codex 桌面 Agent，可读写本地文件、执行命令）：它在项目目录中读 AGENTS.md，通过 `autobiz` 命令行操作本体；MCP 连接器作为备选（2026-10-02 更新）。
- 抽取任务的生产模型暂为 DeepSeek（火山方舟未开通）：relevance 与 extract 均用 deepseek-flash（成本优先，2026-10-02 用户决定；通过回归评测门槛后放行）。首轮审计见 evals/audit-2026-10-02.md。
