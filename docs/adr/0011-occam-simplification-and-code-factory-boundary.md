# 奥卡姆剃刀精简本体；代码生产独立为"工厂"

2026-10-04 自查发现：29 类对象中 18 类无任何数据、30 个行动中 22 个从未执行；商机与方案两套状态重复；"只引用已确认知识"与 1806 条未确认知识矛盾；无数据备份、无版本管理。本人确认原则：先产生结果、先跑起来，不过度工程化。同时本人确认边界：业务知识、方法论、客户资料、案例、需求洞察是越沉淀越值钱的数字资产，放在本系统；纯代码生产是随模型迭代快速贬值的"制造"，放在独立工作台。

决定：
- 本体精简为 20 类对象：内容只留选题 → 发布记录（各时点数据为字段）；商机并入方案（方案状态即销售阶段）；联系人并入线索 / 客户字段；架构设计并入方案章节；课程模块、反馈环、母版 / 变体 / 资产 / 快照移除。
- 里程碑兼任付款节点，新增 record_payment / complete_milestone 与应收账款查询——"钱回到兜里"可追踪。
- 知识确认改为"用到时再确认"：出方案时列出相关但未确认的知识，批量确认后再引用。
- MCP 服务冻结，主入口为 AGENTS.md + 命令行。
- 代码工厂边界：本系统交出工单（需求分析 + 方案架构章节），收回仓库地址（agent_component.repo_url）与交付链接（milestone.deliverables），不存源代码。
- 每日备份（本机 30 份 + 飞书云空间最新 1 份），git 版本管理。

## Consequences

- 被移除的类型将来需要时再加回（本体即代码，无数据库迁移）；加回的前提是有真实数据要放。
- 在本人连续使用两周之前，不再新增业务域或功能，只修使用中暴露的问题。
