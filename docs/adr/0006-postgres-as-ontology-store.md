# 本体真相源改为自建 Postgres + pgvector，飞书降级为工作台与交付载体

取代 ADR-0001。0 号场景跑下来暴露三个问题：AI 无法沿关系推理客户 / 行业 / 知识（多维表格只能逐表分页读取且限流）、没有语义检索、系统无法标准化复制给客户。同时确认两项新约束：3-6 个月内会有 1-3 名助理协作；系统本身要能复制给客户，作为 Agent 定制的样板。

决定：本体对象存储在自建 Postgres（含 pgvector），起步部署在本机，有助理后迁到云服务器。飞书多维表格与文档保留为人的操作界面和对客户的交付载体。

## Consequences

- 本体定义（对象 / 关系 / 行动 / 函数）仍以仓库内声明式文件为唯一权威。由"本体编译器"从同一份定义生成：数据库表、飞书投影、AI 可调用的 MCP 工具。这是复制给客户的技术底座。
- 飞书侧的人工操作（定档、回填等）不做字段级双向同步，而是作为 Action 请求回流，由 Action 层校验后写库，保住"Action 是唯一写入口"。
- Action 执行日志写入数据库审计表，助理权限在 Action 层按行动类型授予，不依赖飞书表格权限。
- 已投影到飞书的 0 号场景 7 张表（ontology/feishu-deployment.yaml）在迁移完成前继续可用，迁移后转为只读投影。
