# 通用对象存储 + 声明式 Action 引擎，本体文件即系统

实现 ADR-0006 时的结构选择。候选：每个对象类型一张表（每次改本体都要迁移数据库），或通用对象表（objects / links / action_log）+ 从本体编译出的只读视图。选择后者：本体演进不需要迁移，给客户复制系统时只换 ontology/*.yaml；按类型展开的视图 v_<类型> 仍给人和外部工具提供看得懂的表。

## Consequences

- 本体文件是可执行的：autobiz/ontology.py 加载并校验（类型、枚举、关系端点、行动引用、角色权限），校验不过系统不启动。
- 简单行动用声明式规则（target / precondition / set / creates）写在本体里；复杂行动写 handler（autobiz/handlers.py）。两者都经同一个引擎：权限检查 → 参数校验 → 执行 → 行动日志。
- 预览 = 在事务里完整执行后回滚。人和 AI 看到的预览与真实执行的结果保证一致。
- 关系可声明 require_verified（如 母版 → 引用知识），把"对外出口闸门"做成数据层约束，而不是只靠提示词。
- 属性存在 jsonb 中，类型约束由引擎而不是数据库保证。因此所有写入必须经过 Action 引擎，store.py 的写函数不得在引擎外调用。
