# 执行层：任务队列 + runner，节点技能作为 Action 适配器

0 号场景的 10 个 Action 需要一个执行体。候选方案：飞书 Workflow（表内自动化）、自建常驻服务、任务队列 + runner（复用已有 runner 约定与九个节点技能）。选择任务队列 + runner：业务规则留在仓库代码里（ADR-0001 的投影纪律），节点技能直接成为 Action 的可替换适配器，且无需在当前规模下维护常驻服务。

## Consequences

- 触发方式按动作性质分流：链式自动触发、定时触发、人工闸门后轮询触发（选题定档）。
- 人工回填类动作（标记发布、回填数据）直接在飞书表内完成，不进任务队列。
- 打分阈值、反馈环算法、体检规则全部在仓库代码中，飞书侧零业务逻辑。
- 执行日志写 data/results/ 自建留存，不依赖飞书记录历史。
