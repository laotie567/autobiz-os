# 前期以飞书生态为本体底座，长期保留开源迁移

> **状态：已被 [ADR-0006](0006-postgres-as-ontology-store.md) 取代（2026-09-30）。**

0 号场景要求尽快上线，团队将扩张，且系统未来本身要作为课程 / 组件对外售卖。决定：前期用飞书多维表格作为本体对象存储、飞书文档作为交付物载体，借助飞书 × 豆包的 Agent 能力跑通闭环；长期目标仍是开源自托管栈。

## Consequences

- 本体 schema（对象类型 / 字段 / 关系 / Action 定义）必须以与飞书无关的声明式文件维护在本仓库，飞书侧只是它的投影；禁止把业务规则只写在多维表格公式里。
- Action 执行日志自建留存，不依赖飞书的记录历史。
- 对象权限模型尽量简单（当前全员内部可见），以降低未来迁移时权限重建的成本。
