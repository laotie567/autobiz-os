# 视频生产拆成两块：创作块（人主导）+ 技术块（机器主导），中间一道人工闸门

2026-10-06，接 ADR-0012。触发：ADR-0012 把 8 步法落成本体后，用户提出更根本的诊断——
**"技术无论如何调整优化，都很难对标 Opus 5.5 的结果"**。因为技术能力有天花板，创作能力没有；
而 8 步法全是技术过程（规则手册 / 卡点 / 导出），没有创作过程。用户给出方向：
**从导演、编排、编剧视角看待每个视频生成任务，再辅以技术实现**，把难题拆成两块。

《四渡赤水》的实测证据支持这个诊断：技术执行全部合格（确定性渲染、卡点、无裁切、三轮视觉审全 PASS），
但**剧本只写了情绪**——"黑场起，水墨群山渐显""标题书法字逐笔落定"。技术块拿到这句无法执行：
"水墨"是什么材质？"逐笔落定"用哪份笔顺数据？于是脚本里规划的插画与笔顺动画**全部落空**，
成片只剩"地图 + 线条 + 字幕"一种视觉语言。这不是执行不力，是**上游指令不可执行**。

决定：

- **两块分工**。创作块（编剧 / 导演 / 编排）产出 `INTAKE.md` / `BRIEF.md` / `SCRIPT.md` /
  `SHOTLIST.md` / `style_guide.md`；技术块（实现）产出 `beats.json` / `check/contact-sheet.jpg` /
  `renders/*.mp4`。方法论落在 `docs/video-production/creative-block.md`，规则手册同步改成两段式。
- **闸门是代码层的**。新增人工闸门 action `lock_video_creative`：创作块不齐备 → 拒绝锁定；
  未锁定 → `check_video_production` 不把进度推进到技术块。不是口头约定。
- **反主观铁律**（来自 OpenMontage，本块最重要的一条）：写"情绪的画面成因"，不写情绪。
  ✗"震撼的揭示" → ✓"航拍大远景后拉；主体逆光成剪影，太阳刚出地平线"。
  主观措辞在不同人、不同模型之间解读差异极大，既不能约束像素，也不能指导下游工具。
- **先算镜数，再写镜头**。按调性定平均停留（庄重 ≈ 3.5 秒/镜），反推应有镜数。
  四渡赤水 180 秒只有 9 幕（平均 20 秒），按"庄重"应有约 51 镜——**这是节奏拖沓的量化根因，
  不是审美问题**。
- **像勘景师描述，不像片库管理员**；每镜填满五要素（主体 / 主体运动 / 场景 / 空间 / 镜头），
  并显式标注主体转移（显现 / 消失 / 切换 / 交错）。CMU/Harvard 的结论：模型描述主体与场景可靠，
  在运动、空间、镜头上不可靠，强制填满五项是最高杠杆的一步。
- **用「但是 / 所以」搭骨架，禁"然后"**。原脚本按时间顺序平铺七段，是中性的纪年；
  改组后每一步都是转折，观众被推着走。
- **历史遗留的处理**。建于两段式之前的项目（如四渡赤水）从未过创作闸门，体检会显式标注
  `legacy_without_lock`：技术产物已存在但**不能据此认为合规**，须补齐创作块并补锁定。

## Consequences

- 创作块是**人工主导**的：系统能查到产物在不在，但判断不了剧本好不好。闸门保证"人看过并确认了"，
  不保证"写得对"——这仍然依赖人。
- 两块之间**允许回头**：技术块遇到实现不了的需求，回创作块改稿，**不许偷偷降级成能做的样子**
  （四渡赤水的插画与笔顺就是被"悄悄省略"掉的）。
- 新增 5 个创作产物使立项成本上升；但对照四渡赤水重做一轮的代价，这个成本是划算的。
- 方法论来源是 OpenMontage（AGPL-3.0），本系统只借鉴其**方法论**（Markdown 指令文件），
  未引入其代码，无授权传染问题。本机已装 OpenMontage（`~/.local/share/OpenMontage`），
  需要真实素材检索（Pexels / Archive.org / NASA / Wikimedia）时可作为技术块的外部工具调用。
- 本体新增字段 `thematic_q` / `tone` / `taste_dials` / `script` / `scene_plan`，
  以及 `lock_video_creative` 行动（本体 29 → 30 个行动）。
